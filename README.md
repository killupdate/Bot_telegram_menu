# ОПТ МЕБЕЛЬ ЮГ — Telegram-бот

Самостоятельный бот без n8n: Python 3.9+ (Docker использует 3.12), SQLite, прямые HTTPS-запросы к Telegram Bot API. Сторонних Python-зависимостей нет. Работает через long polling: домен, открытые входящие порты и HTTPS-сертификат на VPS не нужны. Нужен исходящий доступ к api.telegram.org:443.

## Что реализовано

- `/start` регистрирует клиента и открывает меню, но не создаёт коммерческий интерес.
- Кнопки «📦 Прайс», «🪑 Каталог», «🚚 Доставка», «🤝 Условия сотрудничества» сохраняют тип интереса. `/price` также запрашивает прайс.
- В закрытый канал «ОПТ МЕБЕЛЬ ЮГ | Заявки» приходит username либо `Username: отсутствует`, Telegram ID, тип интереса и две inline-кнопки.
- «👤 Открыть пользователя» всегда содержит `tg://user?id=<id>`.
- «✉️ Написать клиенту» выбирает адресата отдельно для каждого разрешённого менеджера. Бот присылает менеджеру в личный чат карточку выбранного клиента. Следующее обычное сообщение менеджера копируется клиенту, после успешной доставки режим ответа выключается.
- `/cancel` и `/start` у менеджера отменяют выбор. Выбор нового клиента заменяет старый. По умолчанию выбор истекает через 30 минут. Команды не пересылаются клиенту.
- Любое обычное сообщение клиента поступает в «Заявки»: карточка с идентификаторами и кнопками, затем копия сообщения в ответ на карточку, тоже с кнопками. Переписка не ограничивается дедупликацией интересов.
- Текст, фотографии, голосовые и документы передаются через `copyMessage`. Служебные сообщения и некоторые специальные типы Telegram не копирует; бот сообщает об ошибке. Альбом обрабатывается как отдельные сообщения: в одноразовом режиме менеджера отправится только первый элемент, поэтому отправляйте вложения по одному.
- Новый документ в целевом канале обновляет настройку `PRICE_FILE_ID` в SQLite. Файл не скачивается. Первоначальное значение из окружения применяется только при отсутствии настройки в базе. Публикация нового прайса не редактирует `.env`.

Каталог, доставка и условия сейчас фиксируют интерес и предлагают написать вопрос менеджеру. Тексты условий, ссылки на каталог и тарифы не были предоставлены и не выдуманы.

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательный токен существующего бота от BotFather. Не публикуйте его в Git. |
| `LEADS_CHANNEL_ID` | Обязательный числовой ID закрытого канала «Заявки», обычно начинается с `-100`. Название канала не является ID. |
| `MANAGER_IDS` | Обязательные положительные Telegram ID менеджеров через запятую. Username не используется для проверки доступа. |
| `PRICE_CHANNEL_ID` | Канал публикации прайса. Пустое значение означает канал «Заявки». |
| `PRICE_FILE_ID` | Необязательный исходный file_id документа, доступный именно этому боту. |
| `DB_PATH` | Локально `data/bot.sqlite3`; Compose задаёт `/app/data/bot.sqlite3`. |
| `DIALOG_TTL_SECONDS` | Срок действия выбора клиента, по умолчанию `1800`. |

Числовые ID можно взять из старых Telegram Trigger executions в n8n: `channel_post.chat.id`, `message.from.id` или `callback_query.from.id`. Не подставляйте ID клиентов в список менеджеров.

## Подготовка Telegram и переход с n8n

1. Добавьте бота администратором в канал «Заявки» с правом публикации сообщений. Если канал прайсов отдельный, добавьте бота и туда, чтобы он получал публикации.
2. Каждый менеджер должен открыть личный чат с ботом и нажать `/start`. При нажатии кнопки в канале бот не может сам открыть окно личного чата: после уведомления перейдите в чат с ботом и напишите ответ.
3. Отключите Telegram workflow/trigger в n8n. Для одного токена должен работать только один получатель обновлений.
4. После отключения n8n удалите старый webhook командой ниже. Команда сохраняет ожидающие обновления, но её нельзя выполнять одновременно с активным n8n.
5. Запустите бота. Если webhook ещё активен, запуск завершится с понятной ошибкой, не удаляя webhook автоматически.
6. Опубликуйте документ с прайсом в целевом канале. Существующие старые публикации бот не перечитывает; нужен новый пост либо исходный `PRICE_FILE_ID`.

Если PRICE_CHANNEL_ID совпадает с каналом «Заявки», любой вручную опубликованный там документ считается новым прайсом. Автоматические копии документов клиентов исключены. Для других служебных документов лучше завести отдельный канал прайсов. Редактирование более старой публикации не заменяет более новую.

Старая таблица n8n автоматически не импортируется: её выгрузка не предоставлена. При первом запуске база пуста, поэтому прежний клиент при новом интересе получит первое уведомление по новой базе.

## Docker / VPS

Из папки проекта на машине с Docker Engine и Compose:

```sh
cp .env.example .env
# Заполните .env в редакторе
chmod 600 .env
docker compose build
```

Только после отключения n8n, если у бота был webhook:

```sh
docker compose run --rm bot python -c 'import os; from bot.api import Telegram; Telegram(os.environ["BOT_TOKEN"]).call("deleteWebhook", drop_pending_updates=False); print("Webhook removed")'
```

Запуск и просмотр журнала:

```sh
docker compose up -d
docker compose logs --tail=100 -f bot
```

Остановка: `docker compose stop`. Обновление кода: `docker compose up -d --build`.

Контейнер работает без root, с SQLite в постоянном Docker volume `bot_data`; перезапуск/пересборка контейнера сохраняет данные. Не запускайте несколько экземпляров и не выполняйте `docker compose down -v`: эта команда удаляет данные.

Для переноса на VPS скопируйте проект, отдельно защищённый `.env` и резервную копию базы. GitHub подходит для хранения исходников; исполнять постоянно работающего бота нужно на VPS или другом сервере с Docker.

## Резервная копия и восстановление

Создать согласованную копию SQLite во время работы:

```sh
docker compose exec bot python -c 'import sqlite3; a=sqlite3.connect("/app/data/bot.sqlite3"); b=sqlite3.connect("/app/data/backup.sqlite3"); a.backup(b); b.close(); a.close()'
docker compose cp bot:/app/data/backup.sqlite3 ./backup.sqlite3
```

На новом VPS после заполнения `.env` и сборки образа, до запуска бота:

```sh
docker compose run --rm -T bot python -c 'import sys; from pathlib import Path; Path("/app/data/bot.sqlite3").write_bytes(sys.stdin.buffer.read())' < backup.sqlite3
docker compose up -d
```

Восстанавливайте только в новый пустой volume. Старый экземпляр бота перед переносом остановите. База содержит персональные данные: ограничьте доступ к резервным копиям так же, как к `.env`.

## Локальный запуск и тесты

```sh
# Только свой доверенный .env; shell считывает его как команды.
set -a
. ./.env
set +a
python3 -m bot.app
```

Автотесты не требуют токена и не обращаются в Telegram:

```sh
python3 -m unittest discover -s tests -v
```

## Хранение и надёжность

- `clients`: `telegram_user_id`, актуальный `username`, последний `interest`, `last_interest_at`, `last_notified_at`.
- Время хранится как Unix timestamp UTC. `last_interest_at` обновляется при каждом выборе интереса. Дедупликация считается от `last_notified_at`: один клиент получает не более одного уведомления за 86400 секунд независимо от смены типа интереса. Ровно через 24 часа уведомление разрешено. Повторный запрос прайса всё равно выдаёт файл.
- `dialogs`: manager_id, выбранный client_id и expires_at. Выбор сохраняется после перезапуска до истечения срока; недоставленное сообщение не сбрасывает адресата.
- `settings`: текущий `PRICE_FILE_ID`, номер публикации прайса и polling offset.
- `effects`: результаты успешных вызовов текущего обновления. Если подтверждение менеджеру не отправилось, повтор обработки не копирует уже доставленное сообщение снова. После завершения обновления записи очищаются.
- `own_posts`: ID копий клиентских сообщений в канале, чтобы документ клиента не стал прайсом.
- Обновления обрабатываются последовательно. Сетевые ошибки, HTTP 429 и ошибки сервера повторяются с задержкой; `retry_after` учитывается. Ошибка отправки в канал оставляет обновление ожидающим: исправьте права/ID канала, иначе очередь будет ждать. Ошибки токена и конфликт другого экземпляра останавливают процесс. Журнал содержит коды ошибок, без токена и содержимого сообщений.
- Bot API не предоставляет идемпотентный ключ для отправки. Если Telegram принял сообщение, но соединение оборвалось до ответа или процесс завершился до записи результата в SQLite, при повторе возможен дубль. Строгое exactly-once не обещается.
- Telegram хранит неполученные обновления ограниченное время (до 24 часов). Длительная остановка не заменяет резервное копирование и наблюдение за журналом.
- Прямой переход по `tg://user?id=...` зависит от настроек приватности и клиента Telegram. Переписка через бота также перестаёт работать, если пользователь заблокировал бота: менеджер увидит ошибку доставки.

## Проверка в реальном Telegram

1. Клиент нажимает `/start`: меню появляется, уведомления нет.
2. Нажимает «Прайс»: получает файл, в «Заявки» появляется карточка с двумя кнопками.
3. Повторяет запрос: файл приходит снова, второй карточки интереса в течение 24 часов нет.
4. Менеджер нажимает «Написать клиенту», переходит в личный чат бота и отправляет текст. Клиент получает его от бота.
5. Клиент отвечает текстом/фото: в канале появляются его данные и копия ответа. Менеджер снова выбирает кнопку для продолжения.
6. Проверьте клиента без username, второго менеджера, `/cancel` и перезапуск с выбранным адресатом.
7. Опубликуйте новый документ прайса: следующий запрос выдаёт новый файл. Файл, отправленный клиентом в переписке, прайс не меняет.

## Структура

- `bot/app.py` — обработчики и polling.
- `bot/api.py` — HTTP-клиент Telegram Bot API.
- `bot/db.py` — SQLite и состояние.
- `tests/test_bot.py` — автономные проверки сценариев с подменой Telegram API.
- `Dockerfile`, `compose.yaml`, `.env.example` — запуск и настройки.

Документация API: [inline-кнопки](https://core.telegram.org/bots/api#inlinekeyboardbutton), [копирование сообщений](https://core.telegram.org/bots/api#copymessage), [получение обновлений](https://core.telegram.org/bots/api#getupdates).
